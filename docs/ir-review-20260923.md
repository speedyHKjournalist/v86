# IR 设计、功能和 XP 性能复核（2026-09-23）

## 基线与验收口径

依据 [实施计划](v86-ir-implementation-plan.md) 和 [实施进度](ir-progress.md)，固定源代码基线为 `7591db21`（PR #54 合并后）。本轮实际使用用户指定的 `retro-gaming-site/windowsxp/windowsxp_multidisk_C_4G.img`；宿主 Apple M1 Pro，Node v25.6.0，Rust 1.93.1。

XP 比较使用原有 `xp_compare.mjs`：新 VM、相同磁盘、相同 CPU/内存/设备设置、只在内存中记录磁盘写入、三轮交替顺序、关闭诊断和 profiler。终点是首次 800×600×32 显示模式，**不等于完整桌面就绪，也不是游戏/Everest 成绩**。保留既有 CPUID、TSC、执行预算和浮点设置；没有把默认后端改为 IR。

## 已确认并修复的问题

### 短区域分支与入口验证

每个代码 owner 原来只记住最后一个 successor，条件分支交替选择两个已验证目标时，会反复丢掉另一个快速链接。现在保留两个目标；每次仍核对完整入口、两端不可复用的 owner ID、发布状态、generation、epoch 和全部代码页映射。旧索引没有执行权限，回收/替换/SMC 后仍走保守验证。

解释执行的多地址循环还会反复进入完整 admission 后才发现入口不存在。将单项缺失提示扩展为 64 槽直接映射表，每槽比较完整 `CpuEntryKey`，碰撞只替换提示；所有发布、失效、回收及 reset 清除点原样保留，diagnostics 绕过。它只选择既有解释路径，不授权任何已编译代码，也不跳过解释器取指或热度记录。

融合区域可能包含相互重叠的不可变代码窗口。冷创建 owner 时按逻辑页和物理映射合并内容一致的重叠范围，只有实际减少比较字节才保存附加验证计划。运行时仍比较所有字节、保留每个逻辑映射；新路径未成功时按原 source 顺序重新验证，因此不改变 `Unavailable`/`Stale` 与只读捕获回退的行为。原始 snapshot 和 dependency 所有权不被替换。

XP 无插桩 profile 显示，通用 Wasm `memcmp` 是明显热点；实际反汇编确认其逐字节循环。新的比较完整检查 16 字节 SIMD 块、8 字节块和尾部，便携构建使用标量路径。没有哈希替代、抽样、忽略字节或越界读取。观察者返回后直接逐字段核对 CPU 上下文，避免重建第二份数组；XMM 和当前 owner 的代码仍精确比较。

### 编译器活跃变量与 local 分配

HIR/MIR 编译时反复构造和遍历 `BTreeSet<ValueId>`，在短区域频繁编译时产生不必要的堆分配。使用按 SSA ID 索引的位集，保持升序遍历、相同干涉图、相同 coloring 和边复制；冷退出 StateMap、commit 和 block 参数不删减。独立 MIR verifier 继续使用树集合，测试另保留旧集合求解器作为颜色/发射字节对照。位集初始化、空字扫描、克隆和干涉处理均有工作量计费。MIR 表达式扫描改为单个结果向量，保留操作数次序和重复项。

### 融合区域 epoch 检查

在每个 MIR 块入口保留检查；访存、helper、effect 或不透明 CPU 读取之后，下一恢复点仍检查。同步、非共享单 CPU 执行中，已检查 epoch 后仅经过纯 SSA 运算时，不重复加载相同 epoch。诊断及 STI shadow 强制保持原检查。该变换不跨块移动检查，也不减少任何退休预算单位。

### x87 与 MMX 寄存器续执行

x87 寄存器 helper 使用正常 outcome 和 14 项 GPR/FLAGS reload，保留 canonical F80、栈/标签及异常模型，不新增 SIMD 依赖。MMX 同样保留与 x87 的物理别名；涉及 XMM 的传送使用完整向量 reload，其余使用标量 reload。MMX 的隐含访存 MASKMOVQ 和所有内存形式仍终端退出。自动捕获已经覆盖这些寄存器形式；新增逐形式回归保护现有行为，没有额外扩大捕获边界。

debug 下 SSE/MMX 的 OSFXSR 日志可调用宿主。日志发生时原解释器可能尚未读完 displacement/immediate，单纯在 helper 完成后退出还不足以保留任意回调语义。debug CPU artifact 在这种条件下先无副作用退回解释器，不执行日志或退休指令，既有零步 owner 回收防止反复进入；STI shadow 也在开始前退回。含相关操作的 debug artifact 启用 diagnostics 时，无论入口 OSFXSR 值如何均先退回，以防诊断回调在 shadow 内改变守卫前提。release 不含这些 debug guard，正常续执行路径仍执行 IR。直接 helper ABI 保留 barrier 和已完成指令的单次退休。

交叉审查把该保护扩展到普通 SSE 的 `SseCheck`、MXCSR 传送及带 SSE task guard 的非法/保留形式。旧核心实际复现普通 MOVUPS 跳过日志，以及日志回调清除 CR0 后 IR 触发 `unreachable`；新路径在同一指令边界退回。非法 MXCSR 值的终端 helper 另补齐基线在 #GP 前的日志，保留回调改写后的 CPU 状态且不退休故障指令。该项复现为旧 IR 缺少日志回调，不能通过单纯比较最终 #GP 向量发现。

### I/O 权限检查和字符串观察边界

I/O 权限检查可能通过 TSS/bitmap 的 MMIO 读取调用宿主。原标量 IN/OUT 在该检查之后才建立观察快照，回调改写的 XMM 会被后续旧 SSA 覆盖；回归已复现，快照现在覆盖整个权限检查。OUT 还必须在权限成功后读取 EAX，与原解释器顺序一致，不能传出权限回调之前的旧值。

单次 INS/OUTS 原来的分段、权限、访存和写回步骤跨观察点保存 SSA，无法完整保留回调改写的其它寄存器及 address16 的 SI/DI 高位。现在使用既有 CPU 字符串语义的单次有界入口，作为终端 helper；保留原先捕获 src/dst/DF/port 的顺序、故障状态以及成功恰好一次退休。REP 路径未改动。

## 性能与验证记录

最终同镜像三轮交替配对的中位数：

| 后端 | 首次 800×600×32 | 平均 mIPS |
|---|---:|---:|
| 基线 IR，16/64 热度阈值 | 32.998 秒 | 47.089 |
| 本轮 IR，64/256 热度阈值 | 29.013 秒 | 64.417 |
| stage4 IR，64/256 热度阈值 | 29.134 秒 | 63.273 |
| 本轮 core 的 legacy | 19.587 秒 | 126.873 |

相对旧 IR，耗时降低 **12.1%**，吞吐提高 **36.8%**。相对 legacy，耗时仍为 **1.481 倍**，吞吐仅 **50.8%**，**XP 性能门槛失败**。这是代码与编译策略的整体收益，不能归因于某一个 pass。相对 stage4，追加 64 槽缺失提示后的耗时降低 0.4%、吞吐提高 1.8%，不足以宣称单项显著提速。

XP 不同后端在该显示终点的退休数不同（涉及定时设备和等待循环），所以同时报告耗时与 mIPS；严格等量指令性能另由 `fixed_work.mjs` 验证。本结果不支持完整桌面、应用或游戏已经提速的结论。

最终原始配对和 Wasm 校验值：[XP summary](performance/ir-review-20260923/final-xp-summary.json)。首批改动曾达到 38.513 → 41.193 mIPS（+7.0%），保留为阶段记录：[step1 XP summary](performance/ir-review-20260923/step1-xp-summary.json)。

stage4 早先独立三轮的旧 IR / 新 IR / legacy 中位数分别为 38.847 / 49.009 / 98.459 mIPS，耗时 39.371 / 32.441 / 20.946 秒；其中 legacy 一轮为 38.210 秒 / 54.345 mIPS。该组及慢轮完整保留：[stage4 summary](performance/ir-review-20260923/stage4-final-xp-summary.json)。宿主运行状态和 XP 等待循环会影响绝对 mIPS，不能把不同批次的绝对值直接相减当收益；最终采用同批四臂的比较。

热度回归构造 256 个跨页循环代码块，原 128 项表在 15 秒的进度上限内无法发布；扩大保留范围可发布并通过精确退休数检查。但实际 XP 的 512 项默认表导致更多编译和淘汰，单轮只有 33.66 mIPS；上述 512 项热表配置中，提高 cache 容量、加入 probation filter 或调高阈值均未胜过原策略。因此恢复默认 128 项，较大表仅保留为启动期显式实验，单帧扫描最多 128 项。[完整负向实验](performance/ir-review-20260923/heat-policy-experiments.json)

在恢复 128 项后，同一 stage3 core 的单轮阈值实验分别为：16/64 → 43.94、64/256 → 49.72、256/1024 → 51.34、1024/4096 → 50.05 mIPS。更晚编译减少发布/淘汰，但 IR 覆盖率也由约 81% 降至 80%/76%/71%。选择较保守的 64/256 做最终默认配对；执行预算、计数口径和 REP 配额保持不变。历史旧 IR 对照明确指定 16/64，避免新版 JS 默认值污染对照。[阈值实验](performance/ir-review-20260923/threshold-experiments.json)

在 64/256 阈值和 128 项热表下重新测试代码 cache 容量：新版 256/512/768 项分别为 27.550/29.566/28.609 秒、57.54/62.24/56.69 mIPS；stage4 的 256 项为 27.223 秒、58.96 mIPS。512 项的 mIPS 较高但显示终点更晚，不能仅按 mIPS 选为默认；因此保留 256 项。新增缺失提示与 stage4 的单轮耗时接近，其后四臂交替配对也仅测得小幅变化。以上均为单轮探索，不替代验收。[容量实验](performance/ir-review-20260923/capacity-experiments.json)

### 等量指令和编译器测量

保留既有 core/vector 工作负载和门槛：每组至少三轮、状态及精确退休数相同、Tier 2 实际执行、IR 覆盖率至少 95%、IR/legacy 几何均值至少 1、每项至少 0.9。新增 `fp_helpers` 比较全部物理 F80 寄存器有效字节和控制状态，避免只核对 GPR/XMM 而漏掉浮点结果。

默认 scale=1 的 core、vector、fp_helpers 均通过正确性与覆盖率检查，但性能门槛均失败。core 几何均值 1.509，其中 RAM RMW 为 0.878；vector 几何均值 0.959，其中 scalar double、普通/半部 XMM store 未达标。x87 和 MMX 寄存器循环相对旧 IR 分别提高 3.518 倍和 4.120 倍，但相对 legacy 分别仅为 0.959 和 0.391，专项几何均值 0.612。

部分 scale=1 样本仅数十毫秒，同一 legacy 路径在新旧 core 之间也有明显波动。追加 scale=10 的同工作负载三轮对照，用于判断是否存在本轮引入的稳定退化；原始失败结果和验收门槛保留。计时终点为观察到 HLT，异步 stop 的等待时间单独报告，不计入吞吐。

stage4（追加缺失入口缓存之前）的 scale=10 core 四项相对旧 IR 均提高 1.1%–11.4%，但 RAM RMW 为 legacy 的 0.875，core 门槛仍失败；vector 的普通/半部 store 也未过门槛。全部中间结果保留在测量目录。

最终核心的 scale=10 三轮结果如下。core 几何均值 **1.830，本批门槛通过**；vector **1.152，失败**；FP helpers **0.547，失败**。RAM RMW 跨批在 0.87–0.91 附近，本批过线不等于稳定快于 legacy。x87/MMX 相对旧 IR 的收益为 4.127/4.767 倍，MMX 距离 legacy 仍很远。
