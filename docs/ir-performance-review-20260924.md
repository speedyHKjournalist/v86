# v86 IR 设计评审与性能优化（2026-09-24）

本文依据 [实施计划](v86-ir-implementation-plan.md) 与 [进度记录](ir-progress.md)，
对当前 IR 管线在 Windows XP 冷启动上的表现做一次端到端评审，记录已落地的修正、
测得的数据、改变的契约，以及仍然存在的差距。**结论先行：IR 已明显缩小与 legacy
的差距，但在 XP 启动里程碑上仍慢约 10%～17%，尚未超过 legacy。**

## 1. 测量方法

- 工具：`tests/ir/performance/xp_boot.mjs`，里程碑为首次切换到 800x600x32。
- `IR_SYNC_DISK=1`：磁盘读同步完成，排除宿主 I/O 延迟，测的是 CPU 工作量；
  抖动约 ±0.3～0.5 s。默认异步磁盘的抖动约 ±1～2 s。
- legacy 与 IR 使用**同一个** wasm 构建（`jit_backend` 切换），交替运行；
  机器负载较高（load ≈ 20/10 核），以配对中位数为准。
- 编译成本：`tests/ir/semantics/region_bench.rs` 离线重放 XP 启动捕获的
  1828 个区域（`IR_REGION_CORPUS=… cargo test --release region_bench -- --ignored`）。

| 配置 | 同步磁盘里程碑 | 异步里程碑 / 平均 mIPS |
|---|---:|---:|
| legacy（同构建） | 13.1～13.8 s | 19.0～19.6 s / ~134 |
| IR，本轮开始前 | 20.7 s | 26.7 s / 61.6 |
| IR，本轮中期（快速见证表、通知契约等） | 17.0～17.3 s | 22.7 s / ~89 |
| **IR，当前** | **15.6～15.8 s** | **20.9～21.1 s / ~100** |

同步磁盘剖析（当前 IR vs legacy，单位秒）：解释器 4.05 vs 2.35，生成代码
2.05 vs 3.42，IR 编译 0.84 vs legacy 编译 0.45，分派/准入 ≈1.5（见 §4），
GC 0.42 vs 0.11。生成代码本身已快于 legacy；差距集中在覆盖率与每次激活的开销。

## 2. 评审发现与修正（按影响排序）

### 2.1 热度策略失效：最热的入口从未被编译

原策略按"访问次数"计热，存放在 128 项 FIFO 环中（外加 4 次一批的预热过滤）。
XP 启动中该环发生约 380 万次替换：一个入口在被挤出前平均只积累不到 32 次访问。
临时探针显示，57% 的解释执行步数来自**访问超过 256 次却从未编译**的入口
（单个入口可达 16 万次访问、400 万步）。

修正（`src/rust/ir/runtime/schedule.rs`）：解释执行的热度改为**按实际退休指令数
加权**（与 legacy 按页累计指令数的做法一致），存放在 16384 项带完整标签的直接映射
表中；冲突只会让驻留项"老化"，热入口不会被冷入口洪流挤掉。越过阈值的入口才进入
原有的有界环，环因此只保存真正的候选。

阈值为 `hot_threshold × heat_steps`，默认 32 × 4096 = 131072 条指令。扫描结果
（同步磁盘）：1024 → 17.6 s，2048 → 16.7 s，**4096 → 16.3～16.45 s**，
8192 → 17.0 s。阈值越低编译越多，而每次编译的成本高于其节省的解释时间
（见 §4）。访问阈值 < 32 的配置（测试、显式调参）保留精确的逐次计数；
`ir_auto_set_heat_steps(0)` 可恢复逐次语义。

同时修正：解释块在执行**之后**才记录热度，HLT/前缀资格改为在块入口判断，
否则以 HLT 结尾的块会被丢弃（`observed_entries.mjs` 覆盖）。

### 2.2 代码缓存容量小于工作集

原默认容量 256。热度修正后，39%～77% 的解释步数来自"编译过、被驱逐、又回到解释"
的入口。容量 768（wasm 表 900 个槽位中 legacy 在 IR 模式下不使用的部分）时，
XP 启动在 131072 指令阈值下约编译 830 个 Tier-1 区域且**零驱逐**。
不需要扩大 wasm 表；把表扩到 4000 并把容量设为 3000 的对照没有进一步收益。

另外：升档（Tier-2）会取代同一入口的现有所有者，发布时旧记录自然退休，
因此不再为此驱逐另一个仍然活跃的区域（缓存可短暂超出容量 1 项）。

### 2.3 Tier-1 代码膨胀：每条指令一个退出

重放语料中每个区域平均约 9.8 KB wasm，约 30 条 guest 指令即约 320 字节/指令。
反汇编显示：
- 每条指令都有 `PollBudget`，每个 poll 都带一个完整的状态物化出口（一个区域 58 个 `return`）；
- 每个出口写回全部 13 个状态字（8 个 GPR + 标志相关字），约 36% 的存储是把刚读出的值原样写回。

两项修正：

1. **精确稀疏预算**（`passes::sparse_polls`、`mir::control`）。非融合区域只在
   "入口前沿"（从入口经无权重块首先到达的块）和循环头检查预算；每个检查点按到下一
   检查点的**最长加权路径**扣费，余额不足则在执行前退出。块权重 = poll 数 +
   （有恢复映射时的块入口额度），与逐指令方案的工作量单位一致，因此活动退休数仍
   不超过预算，Tier-1/Tier-2 在同一位置停止（`licm.mjs` 覆盖）。若某检查点成本超过
   执行预算，该区域回退到逐指令 poll，避免零进度。融合区域需要逐指令 epoch 检查，
   保持原样。新增 pass 位 `sparse_polls`（位 18）。
2. **区域级 backing 事实数据流**（`mir/allocation.rs::backing_sync`）。原证书只在
   基本块内有效，且在每次内存访问/段地址效果处清空，几乎从不生效。现为全区域前向
   数据流：可能执行的恢复物化只保留值相同的事实，合流取交集；只有
   CMPXCHG8B 这类在正常路径写 CPU backing 的效果与 helper 调用清空事实；只跟踪纯
   架构状态字（GPR、标志、标志操作数、惰性标志字、XMM），PC/退休/其他绝对地址
   从不跳过。Tier-1 默认启用。

效果（重放语料）：wasm 总量 24.18 MB → 14.0 MB（−42%），重复写回 6848 → 569；
单区域编译时间基本不变（约 0.46 ms native）。

### 2.4 端口 I/O 观察者快照

`IN`/`OUT` 续执行每次都复制完整 CPU 上下文与 XMM（`ScalarObserver`），XP 异步启动中
约 1 秒。通知契约下改用 `NotifiedObserver`：只核对 IRQ、续执行 epoch、EIP、
previous_ip、指令计数与 CR0（设备回调无法改变模式状态；复位会改写 EIP/计数；所有通知
代码写都会推进 epoch）。严格模式、诊断和 debug 构建保留完整证书。

### 2.5 其余修正

- **快速见证链**：链式执行中若有记录退休（例如零步退出仍请求链接），不得再进入已退休
  所有者的见证；原实现最多会重复进入 64 次。
- **Tier-2 共享体选伴**：此前改为按记录命中升档后，选伴仍读调度环热度而失效
  （`auto.mjs` 共享体用例回归）；现在从已发布 Tier-1 记录取候选。
- **升档只看近期活动**：新增 `promotion_hits`，在自动策略重新配置时清零；避免历史命中
  在重新配置后触发升档。升档失败即计入抑制计数，同一所有者不重复尝试。
- **融合默认关闭**：XP 上 hot-region fusion 减少约 25% 激活，但每次激活的出口
  剖析与融合编译成本更高（配对：15.47 s vs 15.69 s）。机制保留，
  `ir_cache_set_fusion(1)` 开启，相关测试显式开启。
- **TLB 基址**：生成代码不再每次激活调用 `ir_tlb_base` 导入，而是从固定槽位
  （`global_pointers::ir_tlb_base`，地址 2048，位于 `--global-base` 以下）加载；
  本机生成的测试夹具在 wasm 实例中仍然有效。
- **分配器**：区间分配只在 ≥128 个值的图上使用（Tier-1 编译约省 13%，代码 +0.3%），
  区间分配也执行与图着色相同的 512 活跃值上限。

## 3. 契约与测试变更

| 变更 | 影响的测试 |
|---|---|
| 默认缓存容量 768 | `auto.mjs`、`cache.mjs` 先断言默认值，再显式设为 256 测淘汰 |
| 加权热度（阈值 ≥ 32） | `observed_entries.mjs` 调用 `ir_auto_set_heat_steps(0)` 保持逐次计数 |
| 记录命中升档 | `resident_promotion.mjs`：两种策略都会升档（旧环丢失热度的缺陷已消除） |
| 稀疏预算 | `budget_batch.rs` 在关闭 `sparse_polls` 时验证批处理 |
| 融合默认关闭 | `auto.mjs` 显式开启 |
| TLB 基址槽位 | `entry.rs` 检查 `i32.const 2048; i32.load` 而非导入名 |
| 链式退休 | `notified_validation.mjs` 新增链内代码写用例 |

原生测试 290 项（release 与 debug）通过；CI 矩阵除 `fusion.mjs` 的
"audited helpers retain state across the complete cycle" 外全部通过——该断言在
本轮开始前的 HEAD 上同样失败，未在本轮处理。注意：`cargo test --release` 会以
release 模式重写 `build/ir-*` 下的测试夹具，随后单独运行的 node 差分测试（如
`simd_integer.mjs` 的 debug SSE 延迟用例）会失败；先运行 debug `cargo test` 再测。

## 4. 仍然存在的差距

1. **每次激活的开销约 1.5 s**（关闭内联的剖析构建）：`fast_run` 的簿记约 0.5 s
   （约 15 ns/次，33～45M 次激活），`execute_mode` 慢路径准入约 0.4 s，
   `fast_probe` 约 0.34 s，`execute`/`fast_execute` 自身约 0.26 s。legacy 在页内用
   `br_table` 直接跳转，跨页由 `jit_link_once` 连接。方向：在生成代码内直接链接
   已知后继（经快速表/链接单元的尾调用），把统计从每次激活移出。
2. **覆盖率 81% vs legacy 约 91%**。legacy 按页累计热度，一次编译覆盖整页所有已知
   入口（约 1.8 ms/页）；IR 按入口编译（约 0.9 ms/区域，wasm 内）。页模式
   （`ir_auto_set_page_mode`）在新代码生成下仍然更慢（24.7 s），其热度钩子依赖逐次
   访问记录，需要重新设计。
3. **Tier-1 编译成本**：native 约 0.46 ms/区域，其中 lifting 31%、lowering 35%、
   emit 10%、passes 7%、释放 7%、liveness 6%；wasm 中 dlmalloc 约占 28%。
   只有把单区域成本降低数倍，才能在更低热度阈值下提高覆盖率而不亏损。
4. GC 0.42 s（legacy 0.11 s），与存活模块数量相关。

## 5. 实验开关（`xp_boot.mjs` 环境变量）

`IR_SYNC_DISK`、`IR_HEAT_STEPS`（`ir_auto_set_heat_steps`）、`IR_CACHE_CAPACITY`、
`IR_FUSION`、`IR_REGION_INSTR`、`IR_SOURCE_WINDOW`、`IR_IDLE_MODE`/`IR_SYNC_AFTER`、
`IR_PAGE_MODE`/`IR_PAGE_THRESHOLD`、`IR_DIRECT_T2`、`IR_SYNC_PUB`。
本轮测过但未采用：更大区域（64～120 条指令、480/960 字节窗口，无变化）、
空闲期编译（无变化）、页模式（更慢）、容量 3000（无额外收益）。
