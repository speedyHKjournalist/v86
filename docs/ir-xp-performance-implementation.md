# XP IR 四步实施与验证（2026-09-20）

本记录接续[原因分析](ir-xp-performance-root-cause.md)，以 `b991dccf` 为修改前源码基线。
此次目标是按优先级落实执行、调度、helper 契约和在线编译改进；不以删除准入校验、
跳过异常/中断语义或降低热度门槛获得性能数字。

## 1. 普通边与区域组织

- 每个发布区域缓存一个后继入口键和不可重复的发布身份。快速查找验证前驱/后继
  仍为 Published 且身份匹配；压缩、淘汰、重发与槽位重用使旧链接失效。
  源码、映射、上下文和取指后的验证仍执行。新增 `cache_successor_hits`。
- 缓存没有退休对象时，收集路径提前返回，减少短区域反复进入静止检查的成本。
- 高频终端区域可成为融合路径的最后一个源，允许普通边跨入端口等终端片段。
  内部普通边继续保留 SSA 状态，末尾 observer 保留完整提交/退出 ABI；最多四源
  及三/四源 observer 审计限制仍存在。
- 冷链接本身仍有状态写回和重新准入。此次没有实现任意区域之间的寄存器携带链接。

## 2. 热度记录与覆盖诊断

- 128 项 hot ring 的 BTreeMap 替换为 512 槽固定索引，使用开放寻址和后移删除。
  日常查找/替换不分配树节点；随机替换、冲突、清空与压缩对照测试通过。
- 增加热记录替换次数、入口发现到发布的总/均值所需计数/最大延迟，以及未命中
  的 unseen/heating/ready/pending/failed 分类。发现历史有界，记录被替换后重新计时；
  诊断关闭时不读取发现时间时钟。
- XP 日志新增按显示模式标记的分段 IR 覆盖、每百万退休指令的激活和完整检查。
- 改进保留/选择策略做了实际实验，但没有设为默认：采样保留高热入口版本使
  单轮启动达到 40.884 秒、发布约 7,371 次；两次访问再准入的过滤版本仍增加冷编译。
  最终默认保留原 round-robin 顺序和阈值。过滤版本只通过启动期
  `IR_HOT_FILTER=1` / `ir_auto_set_hot_filter(1)` 显式开启。

这些单次实验用于拒绝明显退化的策略，不作为最终性能收益的配对证据。

## 3. 端口、时钟与 STI

- CPU-control 退出细分为 RDTSC、CPUID、CR 读、CR 写和 CLTS，并单列 STI-check。
  中间诊断样本记录 RDTSC 4,731,886 次，CPUID 24 次，CR 读 8,248 次，CR 写
  3,700 次；当前这个工作负载的 CPU-control 优先对象因此是 RDTSC。
- 标量 IN/OUT、RDTSC 成功后，在 IP/CS/宽度/CPL 匹配且无未完成 shadow 时，
  可以请求冷后继。回调前仍完整物化状态并撤销准入证书；回调后的原始 RAM 写、
  重映射或上下文变化不能继续使用旧代码。这些后继不参与普通 SSA 边的融合预测。
- STI 权限检查的常见实模式/ring 0 路径减少不必要的状态提交；故障路径保留完整
  精确状态。正常 shadow 结束先处理 IRQ，再判断上下文/IF/TF/VM 是否允许冷续执行。
- 尚未把可观察 host 的端口/时钟 helper 改成无同步的跨调用 SSA 执行。

## 4. Tier 1 构建与共享

- 线性窗口末尾允许外部跳转、间接跳转和终端 helper 使用线性 frontend；只有实际
  内部边、STI 等情况进入 CFG，减少逐指令片段构造、phi/lowering 再合并。
- 共享 capture 最多产生四个 Tier 1 或两个 Tier 2 入口；按热度挑选同窗口的入口，
  所有额外入口的源尾长度总和不超过一个原窗口，约束额外冷编译工作。
- 可选 sibling 编译失败时保留已成功主入口，不再丢弃后重编主入口；显式多入口
  API 继续保留整体报错语义。发布仍串行且每帧至多一个产物。
- 这些入口共享不可变 capture，但仍分别生成 Wasm 函数；没有宣称共享一份任意
  多入口机器码或已消除所有构建/发布开销。

## 关闭诊断的最终性能结果

同一 XP 镜像、同一 JS、独立 VM，三个后端交替串行各三次。修改前 IR 使用开始
实现前保存的 Wasm；legacy 和本次 IR 使用本次构建的同一核心。磁盘只有内存写
覆盖层，不修改原镜像。里程碑仍是首次 800×600×32，不能当作完整桌面空闲。

| 中位数 | 修改前 IR（本轮重测） | 本次 IR | legacy |
| --- | ---: | ---: | ---: |
| XP 里程碑 | 32.173 秒 | 31.562 秒 | 18.234 秒 |
| 到里程碑吞吐 | 47.922 mIPS | 51.179 mIPS | 117.383 mIPS |
| 到里程碑退休指令 | 15.418 亿 | 15.876 亿 | 21.452 亿 |

本次相对修改前的中位时间缩短 **1.9%**，吞吐提高 **6.8%**。三次本次 IR 时间
分别为 31.562、31.021、31.960 秒，修改前为 32.684、32.173、31.786 秒；第三轮
并未变快，只有三轮数据，不能把小幅时间变化解释为稳定的大幅收益。不同时间
和吞吐中位数可能来自不同轮次，不能相除反推中位退休数。时钟/轮询导致工作量
不同，吞吐增幅也不等于同一固定程序的加速比。

**XP 门槛仍未通过**：本次时间仍为 legacy 的 1.731 倍、吞吐为 0.436 倍。
原始验收的 33.72 秒/45.69 mIPS 不是此次同场基线，不能用它夸大本次改善。

| 停止时计数的三轮中位数 | 修改前 IR | 本次 IR |
| --- | ---: | ---: |
| IR 退休指令覆盖 | 78.05% | 78.45% |
| 每百万退休指令的 IR 激活 | 52,524 | 51,782 |
| 每百万退休指令的完整检查 | 37,457 | 36,916 |
| 每次 IR 激活的退休指令 | 14.93 | 14.88 |
| Tier 1/2 发布 | 2,433 | 2,479 |
| 缓存淘汰 | 1,225 | 1,216 |

计数取样在停止时，略晚于显示模式事件。激活和完整检查密度仅下降约 1.4%，
平均激活长度仍约十五条指令，说明本轮实现尚未从结构上消除主要区域边界。

暖态固定等工作量、各三轮，精确退休数及最终架构状态一致，IR 覆盖满足测试要求：

## 修改后的 profile 与仍未解决的部分

另开周期 16 的诊断和 V8 CPU sampling，达到里程碑为 34.078 秒，停止为 34.266 秒。
这轮有观测开销，不混入上述配对中位数。退出/退休指令/采样时间守恒检查通过；
细分计时外推仍不可靠，不能用 `estimated_ms` 加总分摊验收时间。

| V8 栈分组（包含 idle 的采样区间） | 占比 |
| --- | ---: |
| IR 准入与分派 | 23.2% |
| 解释器 | 20.6% |
| IR 编译器 | 14.4% |
| idle | 13.0% |
| 生成代码及其 helper | 12.2% |
| IR 调度 | 4.2% |

调度组为 1.460 秒，原分析样本为 3.364 秒，符合消除热路径树维护的方向；
两次均带观测且不是相同退休工作量，不把差值当作可直接相加的启动收益。
当前编译 pipeline 仍累计 5.694 秒/2,446 次，其中 lowering 2.389 秒，HIR
局部分配子阶段 1.295 秒。线性前端和共享 capture 尚未消除这些成本。

新计数显示：

- 普通出口仍占激活的 77.5%；RDTSC 退出 4,771,266 次，占 CPU-control 细分类
  的约 99.86%。后继查找命中 56,835,575 次仍不等于消除了整个准入过程。
- 34,865,301 次目标缺失中，unseen 14,086,749、heating 8,119,348、ready
  11,324,585、pending 1,327,432、failed 7,187。ready 占约 32.5%，说明热度已够
  但尚未发布的时间仍显著；不能将剩余解释器工作归因于不支持指令。
- 有保留历史的 Tier 1 发现到发布平均 54.77 ms、最大 1,467.12 ms；Tier 2 平均
  149.43 ms、最大 2,205.70 ms。这些延迟跨越执行与异步发布，不能相加成 CPU 时间。

因此，本轮四个方向的改动和验证已落地，但“IR 显著超过 legacy”的性能目标
没有实现。剩余主要工作是让普通热路径跨越更多当前区域边界、复用真正的多入口
执行产物，并在不增加冷编译/淘汰的条件下减少 ready 入口等待。编译器内部的
活跃性/局部分配也仍需降本。当前 profile 不支持把 RAM/SIMD 算术本体列为解决
XP 差距的首要方向，故本轮保留既有生成代码优化策略。

诊断汇总：`build/ir-plan-final-diagnostic-summary.json`；采样分组：
`build/ir-plan-final-profile-summary.json`。这份记录明确保留未达标项，不将安全的
冷后继称为跨 observer 的 SSA 续执行，也不将共享 capture 称为共享机器码。

### 复现和产物身份

```sh
IR_BASELINE_WASM=build/ir-plan-baseline/v86-ir-runtime.wasm \
  node tests/ir/performance/xp_compare.mjs /path/to/windowsxp.img build/ir-plan-final-xp
node tests/ir/performance/fixed_work.mjs > build/ir-plan-final-fixed.jsonl
IR_BOOT_TARGET=desktop IR_BOOT_MS=180000 IR_DIAGNOSTICS=16 \
  node --cpu-prof --cpu-prof-name=ir-plan-final-xp.cpuprofile --cpu-prof-dir=build \
  tests/ir/performance/xp_boot.mjs /path/to/windowsxp.img ir > build/ir-plan-final-xp-diagnostic.jsonl
```

XP 比较程序会因门槛未通过返回 1；九次运行本身均完成。汇总为
`build/ir-plan-final-xp-summary.json`，其中包含各次日志路径和 Wasm SHA-256。
