# XP IR 边界成本优化：第二轮（2026-09-20）

源码基线：`19989ac542a51222c893bf521548e3c19c8e7120`。
本轮接续 [上一轮实施及 XP 实测](ir-xp-performance-implementation.md)。
**本轮没有 XP 镜像，未重测启动秒数或 mIPS；不能把下面的代码级验证当作 XP 性能验收通过。**

## 1. 扩大有界 SSA 执行区域

CFG 构建在 64 块预算检查前，把唯一前驱、连续落入的指令串合并，单串最多 32 条。
分支目标、外部入口、STI/shadow 保留边界。重新 lifting 使用逐指令 PollBudget，
原先每条指令的预算恢复点、异常前状态和提交后状态不会因合并而丢失。
96 条直线指令和含 95 条 INC 的循环不再因“一条指令一个参数帧”提前缩短。
指令数、IR 大小、源页和分配工作量上限仍保留。

热点融合一次收集已观察链上的源和预测边，最多四个源、四个预测边；动态目标仍精确比较。
新发布后继不再额外等待八次执行才能尝试加入。达到四来源上限仍允许补入已经捕获的
源之间后来观察到的闭环边；热度采集和融合资格使用同一个谓词，避免闭环补齐被饿死。
这不是无界 trace，也不是删除跨区域准入。未融合的普通出口继续完整提交和验证。

## 2. 真正共享代码的多入口

新增 `compile_cpu_shared_entries`：一次 CFG、优化、lowering、发射产生一个 Wasm 函数。
冷入口先验证 PC/CS/位宽，再按实际 CPU 线性 PC 分派到各自 SSA 入口；宿主不能用任意
函数参数跳过入口检查。同一产物的别名共享一个表槽、不可变代码快照和发布身份。

无客户机指令的冷分派块不消耗客户机执行预算，但必须通过独立 machine CFG 证明：
块中无指令、无物理参数、无恢复状态，所有前驱都是冷入口或已经证明的分派块。
环、客户机回边、孤立块、带工作块均不能取得这个资格。owned-MIR 验证再次检查。

发布、待发布诊断、发现到发布延迟、热度清理、查找、替换、淘汰、SMC 和 restore
均按共享 owner 管理别名。仅替换一部分别名时，旧 owner 保留剩余别名直到其寿命结束。
重叠 x86 解码流或共享编译超预算仍回退为分别验证的产物。

编译预算与发布预算分离：已经编译好的 ready 项可在冷安全点继续发布，不再为了
送到 JS 编译/安装阶段额外等待下一帧编译额度。浏览器安装仍串行、不能在活动客户机帧内发布。
当前正在解释且达到热度的未发布入口优先于普通轮转晋级。

## 3. 时钟、端口和 STI 契约

RDTSC、标量 IN/OUT 新增明确的 normal-reload 适配器。调用前仍提供完整可观察 CPU 状态。
成功后要同时通过控制上下文、XMM 不变、无待处理 IRQ、活动 owner 的全部真实代码字节和
映射复核，才返回 Normal 并继续同一 SSA 区域。GPR/FLAGS 以新的 14 个标量 SSA 值重新载入；
不为整数代码强制引入 v128。不能只凭 epoch 判定原始宿主内存写未发生。

失败时由 helper 退休一次，返回 CPU 拥有的完成后状态；不能重放时钟/端口观察，也不能
用旧 SSA 覆盖宿主改动。异常路径继续由 CPU 交付，不退休故障指令。
PIC/APIC 待处理查询只读，不 acknowledge；被屏蔽的请求也可能保守地拒绝续执行。
因此回调仍需同步，且每次成功续执行仍有字节复核成本，并非“零开销 helper”。

正常 STI/shadow 完成后的内部边：无待处理 IRQ 时保留 SSA，不必先物化全部状态。
有请求时先物化精确完成后状态，执行原有嵌套 IRQ unwind，返回 CPU；异常/终端 shadow
保留原路径。单/嵌套 shadow 不被直线合并跨越，也没有放松中断屏蔽窗口。

## 4. Tier 1 局部分配

单块 SSA 使用定义/最后使用区间分配，避免固定点活跃性求解及完整干涉图。
所有隐藏 StateMap、helper 前后状态、提交状态和出口引用都参与 last-use。
两阶段指令位置允许正常结果在 outcome 检查之后复用失效的调用前快照槽，
有 commit 状态的结果仍与其前状态保守重叠。独立 owned-MIR 验证没有关闭。

多块 CFG 继续使用原有活跃性算法。增量干涉图预算按实际新增关系计费，而非对相同
live set 反复收取完整平方费用；512 活跃值和工作量上限仍在。

可选微基准：

```sh
cargo test --features ir-experimental linear_allocation_paired_benchmark -- --ignored --nocapture
```

它交替运行区间与图分配器，七组、每组 40 次，报告分配阶段中位微秒。一次本地原生运行：

| 直线 INC 数量 | 图分配，微秒 | 区间分配，微秒 |
| --- | ---: | ---: |
| 16 | 350.3 | 44.8 |
| 32 | 726.3 | 85.3 |
| 96 | 2121.0 | 256.0 |

这些是合成程序的**分配阶段**数字，不是完整编译速度，更不是 XP 启动加速比。
微基准不设机器相关 CI 性能门槛；正式对比应在无并发构建/测试的同机环境复跑。

## 回归与诊断

新增 shared-entry 可执行差分：同一实例分别从三个别名运行，对照解释器退休同样数量的指令；
覆盖 16/32 位、优化开关、1/2/5/40 预算，以及错误 PC/CS/位宽、前缀、HLT、入口参数拒绝。
`make ir-entry-tests` 和 IR-core CI 均包含它。

`cache.mjs` 新增同一 owner 内的端口/TSC 回调、直接代码改写、重映射、控制流、XMM、IRQ
变化，以及单/嵌套 STI 后续算术。保留已有页面别名、PTE A 位写、故障、active SMC、
ABA、并发发布完成、restore、表槽回收和 legacy 共存测试。
`auto.mjs` 检查四来源闭环、共享表槽、共享发布取消及精确退休数。

附加诊断字段（已有字段编号不变）：

| 接口 | 字段 | 意义 |
| --- | ---: | --- |
| `ir_cache_entry_stat` | 11 | 当前 owner 仍生效的入口别名数 |
| `ir_cache_entry_stat` | 12 | 共享表槽编号 |
| `ir_cache_stat` | 30 | 有效入口别名总数 |
| `ir_cache_stat` | 31 | 共享函数成功发布累计数 |
| `ir_cache_stat` | 32 / 33 | observer owner 检查 / 拒绝数 |
| `ir_auto_stat` | 25 / 26 | 共享函数编译数 / 提供的额外入口数 |

## 尚未通过的系统性能门槛

仍需同一 XP 镜像、同一 JS/浏览器、关闭诊断，串行交替运行基线 IR、本轮 IR、legacy。
同时报告启动里程碑、退休指令、mIPS、每激活指令数、每百万退休指令激活/完整检查、
ready/pending 缺失、发现到发布延迟和编译分阶段耗时。
多入口冷分派、额外代码验证和扩大区域都可能增加部分工作负载的开销；
不要把功能回归通过写成“已追平 legacy”或“必然获得数倍提升”。
