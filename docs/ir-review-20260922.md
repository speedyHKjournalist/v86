# IR 设计与性能审查（2026-09-22）

## 基线、范围与结论

审查依据：[完整实施计划](v86-ir-implementation-plan.md)、[实施状态](ir-progress.md)，以及 `ir` 在合并 PR #52 后的 `e4622847788c68213e9d4c34fd15853fe2bcf0c6`。该提交的树为 `55b8923decf0ed00516f85ff1ba0fee945f468f9`。本地源代码归档与该树一致，不把前几轮优化当作本轮新增。

**本轮补齐了可确认的快路径缺口，但没有完成“Windows XP 超过 legacy”验收。** 没有取得并执行用户实际使用的 XP 镜像/快照，不能把热循环的 mIPS 当作 XP 桌面或游戏的平均 mIPS。两个固定工作量矩阵均保留失败结果；没有调整 `geomean >= 1 && every(ratio >= 0.9)` 门槛，也没有开启 fast-math、改变 CPUID/TSC 或增加默认执行预算。

## 已修复的具体问题

### 1. 向量 RAM 写每次都退出区域

旧 `lift/region` 遇到 XMM store 截断，backend 成功写普通 RAM 后仍物化状态并返回 CPU。循环中即使只有 MOVUPS/MOVHPS 加计数分支，也无法保留同一 SSA activation。

现在统一经过 `finish_ram_store`：只有经既有 guard 确认为同页普通 RAM、且物理写入页不与当前不可变源代码页别名时才继续。没有代码快照的独立发射器仍保守退出。写入代码页的路径先完成一次写入与退休，再退出；不重放写入。跨页、只读页、空段、MMIO、helper 等保持原精确慢路径。

CPU 对照包含 4/8/16 字节、高半 XMM、MOVNT、MASKMOVDQU、物理代码别名（含 peer）、稍后的故障与退休数。verifier 不只取消“必须位于末尾”的限制，还检查 commit 中 GPR/FLAGS/XMM 与计数关系。

### 2. FP 寄存器基本运算反复进 helper

原 native FP 仅有 ADDPS/SUBPS/MULPS/DIVPS，并对左右输入及输出做重复检查。现在 MIR `NativeFp` 显式携带 packed/scalar 与 single/double 信息。16 种基本形式使用 Wasm `f32x4` / `f64x2`，结果为 NaN 时回到原 CPU helper 保持 payload/sign 行为。

对标量指令只检查有效低 lane，高位保留原目的寄存器；高位 sNaN 不误触发低位回退。CR0.EM/TS 检查不删除。Wasm 计算没有修改 guest MXCSR，结果对照的是当前 v86 CPU 实现，不宣称修复硬件级 MXCSR 舍入/异常模型的既有局限；x87 F80 不变。

### 3. 精确预算下的纯 MIR 批处理

预算耗尽仍必须返回原始逐指令恢复点，因此不能简单删除 poll。新证书只认可最后一个可能观察/故障动作之后的纯尾段，保留必经的第一个 poll。剩余预算足够时一次扣除全部原始单位并执行快体，否则执行未经批处理的原始体。

上限为每区域 4 个体、每体 512 MIR 指令和 31 个可合并 poll、262,144 工作预算；包含 interrupt shadow 的区域以及诊断发射均不批处理。Wasm 超过既有 256 KiB 上限时仅重试无批处理发射一次，不拒绝原本可编译的区域。证书可被 verifier 独立重算；伪造 cost 和 work-limit 失败均有负例。

开关：`ir_passes_disabled: ["budget_batch"]`，bit 17。Tier 1 不启用；公开 CPU 编译入口的正例同时验证 Tier 2 真的生成批处理、disable 后为零。`ir_cache_entry_stat(..., 13)` 是**实际发射**的体数。本轮固定工作量中的短循环此计数为零，因此不把测得的整数提升归因于该 pass；它的执行收益需要在有合格纯尾段的实际区域继续测量。

### 4. 调度器无工作时的重复冷点检查

`visit()` 在同帧 compilation credit 或 scan credit 已用尽时仍可反复进入冷检查。新增负向 hint 在第一次加锁后提前返回，减少重复进入；只有 ready 队列为空才允许该返回，保留已编译模块的异步发布机会。未移除 code generation、mapping、活动帧或 quiescence 的实际校验。

`ir_auto_stat(27)` 计无工作提前退出，`(28)` 计进入冷检查。自动调度回归检查两条路径均被执行；延迟 Promise、取消、源码覆盖和共享 owner 继续使用原生命周期回归。

## 实测结果

Linux x86-64，AMD EPYC 9V74，Node 24.17.0，Rust 1.98.1；同一 CPU affinity、无并行编译、每项三次，current IR/current legacy/old IR/old legacy 隔次反序。每次使用新 VM，预热到实际 Tier 2，固定退休指令数，IR coverage 至少 95%，终态寄存器、FLAGS、XMM、内存及 PC 对照相同。计时止于观察到 HLT，异步 stop 回执单列，不纳入执行时间。

“旧 IR → 本次 IR”是吞吐中位数之比，不是对用户机器的预测：

| 固定工作负载 | 旧 IR → 本次 IR | 本次 IR / 同核心 legacy |
|---|---:|---:|
| `integer` | 1.164× | 1.102× |
| `ram_rmw` | 1.034× | 0.887× |
| `indirect_regions` | 0.970× | 4.916× |
| `sse_register` | 1.020× | 0.773× |
| `sse_packed_double` | 2.153× | 0.797× |
| `sse_scalar_single` | 3.085× | 0.985× |
| `sse_scalar_double` | 3.123× | 1.105× |
| `xmm_store` | 12.428× | 0.616× |
| `xmm_high_store` | 11.555× | 0.399× |
| `xmm_masked_store` | 7.792× | 2.119× |

core 几何平均为 **1.388×，FAIL**（RAM 0.887、PS 0.773 均低于 0.9）；vector 几何平均 **0.876×，FAIL**。整数、间接区域、标量 double 和掩码写已经在本机该测试中超过 legacy，但不能概括为所有 IR 超过 legacy。其他形态尽管较旧 IR 有大幅改善，仍存在明显绝对差距。

旧/新 Wasm 中的 legacy 对照也有漂移；只有三次且向量部分较短，不能把几个百分点的差异当作稳定提升。必须用更多轮次及真实 XP 工作负载复核。各项原始数据（含失败 gate、warm coverage 与最终状态）未删改：

## 验证与验收边界

本轮已执行：向量写差分 debug/release 各 **582** 组；完整 SSE FP 差分 debug/release 各 **88,688** 组，另有 native fast path 专项各 **1,632** 组；预算 ON/OFF 与解释器差分 debug/release 各 **14,400** 组；SIMD 传送、半部/打包传送、掩码传送原有回归。预算覆盖每个切点、计数回绕、16/32 位、非零 CS、lazy FLAGS、代码后故障，比较 GPR/FLAGS/XMM/计数/退出位置。

新增入口 `make ir-budget-batch-tests`；既有 `tools/ir-store-continuation-tests.sh` 扩充到向量并检查两类 CPU 构建。`ir-core.yml` 已接入，两种测试不替换或削减原 CI。

最终全量 `RUSTFLAGS="-D warnings" cargo test`：**256 passed、0 failed、2 ignored**（总计 258 项，原有 ignored 保留）。生成检查、Wasm 执行/解码 oracle 通过。debug、release、无 test-hook 的 runtime 三种核心均通过 auto/cache/warm-chain/missing-hint/publication-yield 回归；计时回执测试通过；production 与 ir-experimental 的 release wasm32 `-D warnings` 检查通过。

这次完整本地验证脚本退出 0，受测 runtime SHA-256 在最终构建后仍相同。浏览器/WebGPU/音频、QEMU/KVM、完整 XP 与游戏矩阵不在本次本地执行结果中，不能标绿。

基线配套工具链导出分支所触发的通用 CI（run `35729281603`，仍是 e462 的生产源码）已有 rustfmt 和 ESLint 失败。Build job 在 rustfmt 后的 KVM/API 等步骤被跳过，不能说通过；ESLint 日志汇总 1,626 项错误。本轮不把全仓历史格式化混入性能补丁，也不以该基线失败证明本 PR CI 已通过。

## 剩余工作优先级

首要验收仍是同一 XP 镜像/快照、同一 CPU/浏览器、同一计时区间的配对运行，同时记录 IR 命中退休占比、每次 activation 的退休数、退出原因、编译/升档时间以及 helper 时间。启动到第一帧、稳定桌面空闲、运行应用、运行游戏是不同负载，不能混为同一个 average mIPS。

在真实 profile 下再判断是否需要扩大经证明的跨区域状态携带/guard 复用，减少 RAM/RMW 与区域入口的重复读写；不能为了追求 100 mIPS 直接增加默认预算、删除代码映射验证、降低异常精度或使用宽松浮点。普通向量 store 仍比 legacy 慢的场景和 scalar/packed FP 差异已经由本轮矩阵明确留下。

IR-13 未通过前，不推进 IR-14 退役旧 emitter。原计划关于覆盖、系统语义、取消与回滚的验收定义保持不变。
